### Q1 · 程序和进程有什么区别？同一个程序跑两次，两个进程能读到对方的变量吗？
- 知识点：1（前置概念：进程）
- 来源：知识点 1 原理第 1 步之前的前置概念补讲
- 当前等级：3
- 上次复习：2026-10-01
- 作答记录：
  - 2026-10-01 · 前置概念复述
    - 用户原话摘要：程序像一个人，平时待在硬盘里啥也不干，需要工作（进程）时去一个专门的工作区（内存）工作；同一份工作跑两次，需要两个完全独立的内存空间，互不干扰，所以第二个窗口拿不到第一个窗口的输入
    - 判定：过关
    - 缺 / 错在哪：比喻有一处细节不贴切——"一个人"同一时间只能在一个工作区，但同一个程序可以同时跑出多个进程；更贴切的说法是"程序 = 一份工作说明书，进程 = 每个照着说明书干活的工人，各有自己的工作台"。第 2 题的回答说明这一点他其实已经理解
    - 等级：3

### Q3 · Python 是怎么知道 Claude Code 进程里发生了什么的？（通道、格式、标签）
- 知识点：1
- 来源：知识点 1 原理第 7 步收尾复述
- 当前等级：3
- 上次复习：2026-10-02（知识点 3 开场）
- 作答记录：
  - 2026-10-01 · 收尾复述
    - 用户原话摘要：SDK 对每一个进程都有一个对话通道，Python 通过它拿到 agent 目前的状态；通道内容是 JSON（计算机通用的数据传输格式），其中 type 记录当前 agent 的状态，Python 读这部分就能让用户准确了解目前状态
    - 判定：过关（核心对：子进程通过通道写出 JSON，Python 读取，靠 type 区分），细节当场纠正
    - 缺 / 错在哪：① 通道没说准——是 Claude Code 子进程的标准输出，SDK 在 Python 进程这边读；② 漏了"一行一条消息"（靠换行知道一条在哪结束）；③ type 不是"agent 的状态"，而是"这一条是哪一类内容"（开头配置 / 模型产出 / 工具结果 / 结束账单），Python 按类别分别处理，不只是给用户看状态；④ 漏了 SDK 把每行转成对应的 Python 类（`SystemMessage` / `AssistantMessage` / `UserMessage` / `ResultMessage`）

  - 2026-10-01 · 批改中追问（第一次运行后，用户把多出来的 `SystemMessage` 当成模型产出；纠正后追问"怎么判断一条消息是不是模型产出、`SystemMessage` 是谁写的"）

    - 判定：未过关，再追问一次
    - 缺 / 错在哪：① "谁写的"答错——每一条消息的原始那一行都是 Claude Code 子进程写到标准输出的，Python 进程（SDK）只是读进来、翻译成对象；`SystemMessage` 是 Claude Code 程序关于自己状态写的事件，模型内容由它转发、装在 `AssistantMessage` 里；② "三个对象"指向不明（可能指文字 / 工具调用 / 思考三种内容块），且判断的第一步应该看消息类（是不是 `AssistantMessage`），只看内容块会把 `UserMessage` 里的工具结果块误当成模型产出

    - 判定：独立答出，不完整
    - 缺 / 错在哪：格式（JSON）、标签（`type` 的值）、翻译成对象都对，比上次进步；漏了通道（Claude Code 子进程的标准输出）和"一行一条消息"

### Q6 · 为什么 `AssistantMessage.content` 可能是空列表？写代码时意味着什么？
- 知识点：1
- 来源：知识点 1"必须记住的第 4 件事"（第二次运行 #2 的真实现象）
- 参考答案要点：SDK 翻译内容块时只认识 text / thinking / tool_use / tool_result / server_tool_use / advisor_tool_result，不认识的类型直接丢弃、不报错（0.2.162 `message_parser.py`）；所以 Python 看到的是翻译后的结果，不一定等于命令行程序写出的全部。写代码不能假设每条 `AssistantMessage` 都有文字。补充（2026-10-02 知识点 2 实测）：看起来"空"的 `AssistantMessage` 也可能装着代码没打印的块，例如 `ThinkingBlock`（模型的思考），所以要分清"真的空列表"和"有块但没打印"
- 当前等级：2
- 上次复习：2026-10-02（知识点 3 开场）
- 作答记录：
  - 2026-10-02 · 间隔复习（知识点 2 开场，隔夜）
    - 用户原话摘要：`AssistantMessage` 是 Python 的一个类，装 agent 输出的 assistant 内容；只要 agent 输出了，不管有没有具体内容，Python 都会如实获取并输出
    - 判定：答错
    - 缺 / 错在哪：原因说反了——不是"agent 输出了一条空消息、Python 如实转交"，而是命令行程序发来的内容块里有 SDK 不认识的类型，SDK 翻译时直接丢掉，才剩下空列表；Python 看到的是翻译后的结果，**不是**如实全部。也没说出写代码的含义：不能假设每条 `AssistantMessage` 都有文字
    - 等级：0
  - 2026-10-02 · 间隔复习（知识点 3 开场，新对话）
    - 用户原话摘要：偶尔 assistant 对象收到的是其它类型的回答，对象默认留空、不报错，于是就是空的；这意味着模型说了些不重要的东西
    - 判定：原因基本对（比上次进步：认不出的类型被留空、不报错），写代码的含义答错
    - 缺 / 错在哪：① 没说清是谁丢的——Python 程序这边的 SDK 翻译时丢掉的，Claude Code 程序其实发了内容；② "模型说了些不重要的东西"不对——被丢掉的不一定不重要，Python 看到的不是全部；知识点 2 里那条"空"消息其实装着 `ThinkingBlock`（模型的思考），只是代码没打印。正确含义：不能假设每条 `AssistantMessage` 都有文字，也不能把"看起来空"当成"真的空"
    - 等级：2

### Q7 · 模型碰不到你电脑上的文件，它是怎么用上"读文件"工具的？（按顺序：谁把什么交给谁）
- 知识点：2
- 来源：知识点 2 原理第 7 步收尾复述
- 参考答案要点：① Claude Code 把问题 + 工具清单（名字、用途、参数格式）发给模型；② 模型回一张调用单（工具名、参数、编号）；③ Claude Code 在你电脑上执行工具；④ Claude Code 把全部历史 + 标明编号的结果再发给模型；⑤ 模型写出回答，或再开调用单（回到 ②）——这个循环就是 ReAct
- 当前等级：2
- 上次复习：2026-10-02（知识点 3 开场）
- 作答记录：
  - 2026-10-02 · 收尾复述
    - 用户原话摘要：Claude Code 在起作用；我的问题和 Claude Code 的工具说明一起发给模型；模型了解问题后从工具箱里找最合适的工具，发给 Claude Code 一份说明（工具、任务、编号），让 Claude Code 去做事
    - 判定：过关（前半段完整准确），后半段当场补上
    - 缺 / 错在哪：停在"让 Claude Code 去做事"，漏了回程——Claude Code 执行后把全部历史 + 结果再发给模型，模型据此回答或再开调用单（循环）。第 4 步时他答出过这一点，判为遗漏而非误解
    - 等级：2
  - 2026-10-02 · 间隔复习（知识点 3 开场，新对话）
    - 用户原话摘要：我的需求和 Claude Code 的工具单一起发给模型；模型拿到需求和工具，让 Claude Code 按要求完成任务；Claude Code 完成后把结果给回模型；模型根据任务需求搞懂这是哪个任务的结果，最后按规定输出
    - 判定：独立答出，主链完整（上次漏的回程这次有了），两处不完整
    - 缺 / 错在哪：① 发回结果时要连同前面全部对话一起发（模型不记事）；② 模型看完结果不一定直接回答，也可能再开一张调用单，回到 Claude Code 执行——这个"可以转好几圈"才是 ReAct 循环。另外"让 Claude Code 完成任务"可以说得更具体：模型开的是调用单（工具名 + 参数 + 编号）
    - 等级：2

### Q21 · 路径怎么不再写死？项目根目录靠什么算？从哪个文件夹运行为什么结果都一样？`/` 和 `+` 接路径有什么区别？
